# ridge — glossary

Its purpose is to keep the user and Claude Code from drifting apart on what a
word means. A term is added or renamed in the **same PR** as the code change.
Words that come from furrow are canonical in
[furrow's glossary](https://github.com/akira-toriyama/furrow/blob/main/docs/glossary.md);
only **words whose meaning was born on the ridge side** live here.

## Position

| Term | Meaning |
|---|---|
| **ridge** | furrow's TUI front-end. This repo. |
| **vista** | furrow's GUI front-end (Tauri v2 + React). ridge's sibling. |
| **front-end** | Something that drives furrow **through CLI/JSON** (the no-import contract and its reason: [CLAUDE.md](CLAUDE.md)). |
| **Provider** | The one door through which ridge reads and writes tasks (an interface). The port is declared by `internal/board`; the adapters are `internal/store/furrowstore` (execs `furrow`) and `internal/store/memstore` (the fixture). The division of labour between the Model and Persist* (the Model applies, the store records, Persists run off the UI thread) is canonical in the head of `internal/board/provider.go`. The exception is the **store-first** family (below). |
| **store-first** (write) | A write that is **not** applied optimistically. Quick add, the epic family (`EpicAdd`/`EpicSet`/`EpicActivate`/`EpicDeactivate`/`EpicDone`/`EpicReopen`/`EpicDepAdd`/`EpicDepRm`) and the Sweep's three (`Archive`/`Unarchive`/`Tidy`) — the list is canonical in the store-first section of `internal/board/provider.go`. The reason is that "what this write means" lives on furrow's side — activate **refuses rather than steals** the per-repo slot, add mints the id, progress/stuck/open_deps are furrow-derived. So the board changes nothing; the write rides the persist queue and **converges on the re-read after it lands**. A refusal needs no rollback (nothing was applied), but **if a store-first write landed earlier in the same drain, the re-read is still required** — otherwise that change stays off the board until the next `r` (`persistOp.noLocal` / `unreadLanded`). |
| **persist queue** | The serial queue of optimistic writes (`internal/ui/persist.go`). One in flight at a time — a reorder's anchor (`--before <id>`) depends on the result of the write before it. On failure the rest is discarded and the store re-read = rollback. Quit waits for the drain. |
| **reconcile** | The silent store re-read after the persist queue drains. Converges the board on the store's truth — respaced priorities, closed stamps and so on. |

## Views

| Term | Meaning |
|---|---|
| **Board** | The kanban. Lanes are columns, cards are tasks. The default view. |
| **Table** | The flat tabular view. `v` toggles with Board. Columns: id/lane/marks/v-e/title/repo/epic/labels/due/updated/deps. |
| **Graph** | The **dependency graph**. Rooted at one task, a layered diagram with blockers on one side of the axis and "what starts moving when this closes" on the other (which screen axis is the **orientation**). `S` / `Shift+Space`. |
| **orientation** (of the Graph) | Which screen axis the Graph's layers run along. Two values — **top-down** (default: blockers above, "what starts moving" below) and **left-right** (blockers left) — switched with `o` (`-graphlr` headless). **Both position and arrowhead** always point the same way (arrowheads `▼` / `▶`), so the arrows never have to be relearned. The "use the given axis, negotiate the other" relation flips too: top-down is given the width and negotiates title lines, left-right is given the height and negotiates box **width**. Ranks that do not fit the width are dropped and counted in the header, and **the drawn window follows the cursor** (the selection never leaves the window). At design time (2026-08) the real data's ego graphs were at most 6 ranks (a longest chain of 5 edges), and 6 ranks × the floor width fits exactly 240 columns — a board beyond that enters the "drop ranks" path (`graphview.go`). The rank count is the longest path inside what the radius included, not the radius (see ego-graph), so a deep board enters it at the default radius: ridge-test does at 240 columns. Not persisted across sessions (like the hop radius). |
| **Map** (dependency map) | **The view that surveys every dependency cluster on one screen.** Where Graph is "rooted at one task", this has no root. `T` (the whole-board version of `t`, that task's dependency tree). No lines are drawn: **indentation = depth, `←` = the blocker named**. The numbers shown per cluster and for the whole (unblocked / blocked / the task that blocks the most / the longest chain) can **all be recounted from the marks on the rows of the same screen** (`unblocked + blocked + done = nodes` — counting pure topology instead puts "7 unblocked" above a row of `v`). A node reachable by two paths appears only once. A filter never removes rows; it mutes them and counts in the header. |
| **Roadmap** | The **due timeline**. A full-screen view with the **open** tasks that have a due, one row each in due order, and `◆` placed on a time axis. `C` (calendar — `R` is sync, and `D` was rejected because lowercase `d` = done is a write). No due, not shown (as in GH); done, not shown (a kept promise is not a promise). `┊` = the today line; right of `◆` the owning epic's `▤` chip (epics have no date, so GH's vertical marker cannot exist — the in-row chip is the minimal form). The filter follows the Map's contract (mute, do not hide, count in the header). Read-only — changing a due by drag waits until the read-only view has proven its worth (t-7t28). |
| **zoom** (of the Roadmap) | How much of the calendar one cell is. Three values, day (default) / week / month, with boundaries **as the calendar has them** (Monday-start weeks, the first of the month). `z` cycles — the full-screen views' `z` = "how much fits on the screen", followed. h/l pan the window (one press = the zoom's natural period: 7 days / 4 weeks / 3 months). Not persisted across sessions (like the hop radius). |
| **Swimlane** | **A two-dimensional grid of lanes × group by.** The board's lanes across, the group-by values down as "bands": `furrow ls --tree` (grouping by epic) given a second axis. `W` (`w` is unassigned, so dropping the shift does nothing — the same licence as `C`). The axes are the slice panel's three, repo / label / epic (default = epic; `tab` cycles and **never touches the slice selection** — group by is not a filter). Bands are **folded** by default (a folded band = one line of per-lane counts; unfolding drops its tasks into the same columns). A band's header line is identical folded or unfolded; only `[+]`/`[-]` changes. Tasks with no value land in **one band at the end** (`(unfiled — no box)` / `(draft — no repo)` / `(no label)`). A task with several repos / labels appears in **every** matching band (as in the box overview). `⏎` issues the existing slice term (a valueless band refuses and names the query to type instead), `z` switches scope open/all (under open the done lane is empty by definition but **the column stays** — a grid whose column widths move with the scope cannot be checked against the board), `^u/^d` page. The count above a lane column is **tasks**; the sum over the bands is **placements**, and only when they differ does the header say `N placements`. When the width is short, lanes are **dropped from the tail** and the header says so (`lanes 1-4 of 6`) — narrow columns are never laid out silently. The filter follows the Map's contract (mute, do not hide, count in the header). **Read-only** (the reason is canonical in WHY NO WRITES at the head of `internal/ui/swimlane.go`). |
| **band** (of the Swimlane) | One row group of the Swimlane = one group-by value. **Fold/unfold** with `space` (only the unfolded set is held — folded is the default, so 57 bands can still be an empty map). Folding moves the cursor to the band's header (a cursor left on a vanishing row is thrown to the top on the next frame, which reads as an unasked-for scroll). |
| **rail** (of the Swimlane) | The fixed-width region at the left of a band header. On the header line: `[±]` + mark + label + total; on task lines: the selection bar and the band's continuation rule. Without it the band label would end before lane 0's count (about 25 cells at 240 columns), too short for a CJK epic title. |
| **saved view** | **A name on a bundle of {layout, q, sort, slice}** (the equivalent of GH Projects' view tabs). Canonical in the `[[view]]` entries of `~/.config/ridge/views.toml` — **the one file ridge writes**, and only on an explicit `V` (it is saved data, not config). It is not kept on furrow's board — how the board is shown belongs to the front-end, and if vista ever wants to share it, the request goes back to furrow. The tab strip sits right of Board\|Table on the title line: `1`-`9` switch, `V` saves (inside the roadmap view too). **At most nine** — the digits are the only way to reach a tab, so a tenth new view is refused with a reason, and hand-written tenth-and-later views are displayed only (`viewtabs.go`). Read once at startup, written only by `V`; the file's rules (clamp, whole-file rewrite, last-writer-wins, writing through a symlink) are canonical in `internal/views/views.go` (the package head and the Load / Save doc comments). layout has three values, board\|table\|roadmap (graph needs a root task, map/boxes are population switches, so neither qualifies). |
| **unsaved dot** (●) | The mark on the active saved view's tab meaning "the current state has drifted from the saved bundle" (GH's blue dot). Pressing the digit again = rewind to the saved bundle; `V` = save the drifted side. |
| **Sweep** | **furrow's maintenance passes on one screen: `archive` / `tidy` / `unarchive`.** `X` (uppercase like every full-screen opener; `x` is unbound in normal mode, and inside the view it skips a row). Four sections under one cursor — the done tasks past the age guard (`furrow archive -r '' --json`, dry run, `older_than_days` echoed in the header), tidy's two classes (`done-deps` = open tasks with edges to done tasks, `unknown-keys` = shards carrying keys this furrow does not know), and the archive store (`furrow ls -r '' --archived`). **Every candidate is furrow's**; ridge computes none (the fixture's `memstore` mirrors the rules for -dump and tests only). Writes go through a **gate**: `⏎` names the write in the header line, a second `⏎` applies, any other key cancels (`ctrl+c` still quits — the escape hatch every surface keeps). The archive write sends the **explicit id list** on screen minus the rows `x` skipped (`furrow archive <ids> --yes`) — never the id-less form, which is the aged sweep; an empty list is refused before exec (`board.ValidateSweepIDs`). A tidy write is a whole class (`furrow tidy --done-deps|--unknown-keys --yes`; furrow has no per-edge form, so the gate states the count). Restore is one row (`furrow unarchive <id>`; no `--yes` — furrow guards only the destructive direction). All three are **store-first**: the previews and the board are re-read when the write lands (`sweepAfterWrite`, off the same re-read the epic family converges on). Rows are keyed section+id, never by index: a re-read reorders the list and the cursor must stay on its row. |
| **peek** (the detail pane) | The overlay that shows the selected task's details alongside. `Space`. |
| **cluster** (dependency cluster) | A connected component of tasks joined by dependency edges. One Map panel = one cluster. On the real data about 10 among the open tasks, median 2 nodes (2026-09-03: 13). Canonical in `internal/board/cluster.go` (`Graph.Clusters`) — furrow has no equivalent door, so ridge derives the topology, and only that, itself. |
| **scope** (of the Map) | What the Map counts. `open` = drop done tasks with their edges (default — a finished dependency is not a blocker) / `all` = everything. `z` switches. |

## mode (who owns the keyboard)

The current mode is shown **always** as the ⟨…⟩ token at the right end of the
title line (only the six full-screen views — graph, Map, Boxes, Roadmap,
Swimlane, Sweep — draw their own title line = every view's tab strip + their
own token). The `?` help is sectioned by these mode names, and the section of the
current mode carries "you are here". This table is canonical for the tokens'
formal names.

| Term | Token | Meaning |
|---|---|---|
| **normal mode** | ⟨NORMAL⟩ | The default mode. Cursor movement, view switching, the entrance to each modal. `?` opens in normal mode, in move mode and in every full-screen view; it cannot be pressed while a modal is taking input — the keyboard is the modal's. |
| **move mode** | ⟨MOVE⟩ | Lift a card and put it down elsewhere (see the operations table below). |
| **filter mode** | ⟨FILTER⟩ | `/` gives the filter bar the input. |
| **edit mode** | ⟨EDIT⟩ | The edit menu (edit overlay) has the input. |
| **add mode** | ⟨ADD⟩ | The quick-add modal has the input. |
| **slice mode** | ⟨SLICE⟩ | The slice panel has the input. |
| **epic mode** | ⟨EPIC⟩ | The epic overlay has the input (`epicmode.go`). Entered from the slice panel's epic axis; `esc` returns to the panel. |
| **graph** | ⟨GRAPH⟩ | Outside the mode enum but owns the keyboard — a full-screen view, in effect an eighth mode. |
| **dep map** | ⟨MAP⟩ | Likewise a full-screen view outside the mode enum (`T`). The `?` section name is this row's word **verbatim** (`helpSection.title` in `keys.go`). |
| **box overview** | ⟨BOXES⟩ | Likewise a full-screen view outside the mode enum (`E`). Landed in PR #60 but was missing from this table (added with the Roadmap PR). |
| **roadmap** | ⟨ROADMAP⟩ | Likewise a full-screen view outside the mode enum (`C`). |
| **swimlane** | ⟨SWIM⟩ | Likewise a full-screen view outside the mode enum (`W`). The `?` section name is this row's word verbatim. |
| **sweep** | ⟨SWEEP⟩ | Likewise a full-screen view outside the mode enum (`X`). The `?` section name is this row's word verbatim. |
| **drag** | ⟨DRAG⟩ | Not a mode (`dragState`), but the token shows during the gesture. |

## Operations

| Term | Meaning |
|---|---|
| **move mode** | The reordering gesture from GitHub Projects. `Enter`/`m` lifts (**but with the peek open / in the Table view the same key opens the edit menu** — the branch in `normalkeys.go` is canonical) → arrows and hjkl step by one, uppercase K/J/H/L go to the end in that direction → `Enter` commits / `Esc` cancels. Maps 1:1 onto furrow's sparse-priority reordering. |
| **drag** (DnD) | Carry a card with the mouse. The mouse form of move mode; the commit path is the same (`commitMove`). |
| **ghost** | The translucent card that follows the cursor during a drag. A lipgloss Layer (Z=99). |
| **drop indicator** | The mark showing where the drop lands. A Layer, but **without an ID**, so `Compositor.Hit` never picks it up (it does not eat clicks). |
| **drag threshold** | The minimum travel before a press counts as "grabbed". Without it a one-cell tremor commits as a move (a bug lazygit actually hit). |
| **jump-to-blocker** | `>` jumps the cursor to the first open blocker, `<` goes back. A stack, so it can descend any number of levels. |
| **sync (`R`)** | `furrow sync --json` (git commit/pull/push) → store re-read. Never runs automatically — a v1 decision (t-s86r). `r` is the re-read alone. Every body this session wrote and no sync has committed since is named with `-b` (why: `furrowstore.Store.Sync`'s doc — a bare sync leaves a modified body for its author, and furrow's journal of its own writes does not carry `edit --body`, t-sbcn / t-x9nm; the set is per process, so a body written in a session that never synced is reported like a hand edit next time). The landing note reads furrow's progress and survives a busy queue and a failed re-read: `published N: <ids>`, `NOT published N: <ids> (modified here — furrow sync -b <id> publishes yours)`, `stash left behind: N`. `complete` is furrow's "nothing left behind" verdict, which on the exit-0 path ridge reads is "fully published"; a failed push exits non-zero, whatever `complete` then says, and reaches the line as an error (the verdict leads the line, the error follows). Headless: `-demo synced`. |
| **filter (-q pass-through)** | The filter bar passes straight through to furrow `-q`. ridge holds only the raw string and the id set the store returned (the verdict); the grammar is furrow's alone (t-ehk7). While typing, and on a refusal, the previous verdict is kept and ⚠ shown (the board never empties). memstore has an evaluator for -dump and tests. The vocabulary (`furrow vocab query-is`/`query-presence`) and matching rules were measured against the real furrow, and syntax it cannot honour (ordinal/date comparisons, graph qualifiers) is **refused** like furrow does — never a silent zero. |
| **edit menu (edit overlay)** | The field-editing modal opened by `Enter`/`m` in the peek or Table (`editmode.go`). Two stages: menu → sub-editor (1..5 picker / toggle list / deps list / refs list / text input / checklist cursor). Applied optimistically via the persist queue; everything `furrow set`-shaped is merged into one write. deps is a one-way list (⏎/x removes, `a` + task id adds; acyclicity and existence checks are furrow's, ridge only mirror-validates). refs is a one-way list of the same shape (⏎/x removes, `a` + file:line/URL adds; the `furrow ref` equivalent — a sequence in insertion order, never sorted). repeat is a text input, the `furrow set --repeat` / `--clear-repeat` mirror (empty clears): it opens seeded with the stored rule — furrow's compiled RRULE, which `--repeat` reads back as a raw rule line — the spelling is furrow's to judge (a refused rule rolls back like any refused write; the optimistic apply keeps the spelling as typed until the re-read brings the compiled form), it needs a due and an open task — furrow's two refusals, in its order — and the row states which applies (`— needs a due first` / `— closed; reopen it first`, one `repeatCell` for the row and the press) and refuses the press, the same before-the-press doctrine as the epic overlay's `active` row; **every rule write re-anchors the series at the task's due** — the CLI's own semantics for `--repeat` alone, a re-commit of the seed included (still furrow's to judge: an UNTIL the due has since passed is refused as spent) — while a due write alone moves this occurrence and never the anchor, and clearing the due under a rule is refused (drop the rule first; both drops in one write furrow accepts). **Not shown**: furrow's bind-time advisories — an anchor the rule does not land on (#339), a February 29 (#341) — are stderr prose on exit 0, which the exec layer does not read; t-gf2e (requests) asks furrow for an envelope key. Headless: `-demo editrepeat` (the input), `-demo editnodue` / `-demo editclosed` (the two precondition rows). |
| **box overview** | The full-screen view opened by `E` (`boxboard.go` / `boxboardview.go`). **Every box, grouped by repo.** Not a graph, and that is a measurement — the real board has 150-odd boxes and a **single-digit** number of epic-to-epic dep edges (2026-08-28: 4 edges over 153 boxes / 2026-09-03: 5 over 163), so an ego graph or connected components would only bury the content in isolated nodes. A handful of edges ride the dep map's inline `←id` tag. Repo is the grouping because it is the one axis every box has (zero repo-less boxes on the real board, 31 repos), and because furrow allows one active box per repo, so `▶` read down the frame is a checklist of "which box each repo is working out of". A box spanning two repos appears **under both** (removing it from one leaves that repo's list silently incomplete). Rows use the `slice panel`'s grammar (measure the suffix first, give the rest to the title; lifecycle marker leading, closed dimmed) — with one declared divergence, the marker column's third rung (see `▶`/`◆`/`v`). `⏎` only issues the existing `epic:` slice term (no new slicing mechanism; works for closed boxes too), `m` opens the overlay, `z` includes closed, `^u/^d` page. |
| **epic population** | Epics are read with `epic ls --all`, so **closed boxes are on the board too** (`EpicInfo.Closed`, zero value = open). Each surface shows a different population: `Board.Epics()` is **open only** (a task's epic-reassignment list indexes this slice **by position**, so a closed box in it would offer a finished box as a target and shift every id after it; the slice panel looks up by id, but the reason it does not list finished boxes by default is the same), `Board.EpicsAll()` is everything, `Board.Epic(id)` resolves closed ones too. Two reasons to hold closed boxes: a dep can be told apart as "a closed box" versus "an unresolvable id", and `epic reopen` has something to point at. |
| **slice panel** | The left panel opened by `s` (`slicemode.go`), 32 cells wide. Three axes — repo / label / epic — and on the epic axis the population is **open boxes only** by default: `z` widens it to include closed (the same key and word as the dep map's scope switch, and **the only road to a box closed in an earlier session**). Selecting a row **issues a -q term**, ANDed with the typed filter (GH's slice semantics); it is radio behaviour (reselect clears, switching axis clears), it survives closing the panel, and it shows in the filter bar as `slice <term>`. `g`/`G` jump to the ends. On the epic axis `m` opens the epic overlay and `A` creates a box; on the other axes both **refuse with a reason** — no dead keys. Each axis' third chrome line is the **scope line** (`N repos` / `N labels`; on the epic axis `N open · +M closed  z`), which names the population it is hiding and the key that shows it — the note cannot, because the next `sliced to …` overwrites it. The bottom row is a **readout** naming the row under the cursor in full while the panel holds the keyboard; the panel is modal, so `?` cannot be pressed and the note is the only place its keys are announced (rewritten on every axis switch). An epic row leads with a lifecycle column (`v` closed / `▶` active, drawn before the title is ever cut), is as tall as its title needs up to two lines with furrow's numbers on the last line, carries the box's **short repo** where the title does not already open with it (shortened rather than dropped when cells are few), and a closed row is dim end to end — the cursor and the issued slice outrank the dim. While an epic dep waits on an open box the row shows `→N`, furrow's derived `open_deps` counted as is: information, not enforcement. Every one of those choices rests on a measurement of the real board, and the measurements live beside the constants they justify, at the head of `internal/ui/slicemode.go` and next to `sliceRepoMin` / `sliceWrapCap` — not here, where a copy of them went stale twice. |
| **epic overlay** | The box-management modal opened with `m` from the slice panel's epic axis (`epicmode.go`). The `furrow epic add/set/activate/deactivate/dep` equivalent. Rows: the ten `epicFieldName` names in `epicmode.go` — title / goal / active / standing / pinned / labels / repos / deps / meta / closed — with furrow's derived `d/t done` and STUCK above them (not editable, so not rows). Every write is **store-first** — the board keeps showing the old value until it lands, and the note says what is being waited on. A second press while in flight is refused (the row still shows the pre-write value, so the second press would aim at a board nobody has seen; furrow accepts a re-activate of the same box with exit 0 and `changed:[]`, so the refusal is the screen's, not furrow's). The `active` row states its preconditions **before** the press (`no — slot held by <id>` / `no — attach a repo first`) — furrow refuses rather than steals the per-repo slot, so an exit 2 must never be the first news. activate's `--reason` input doubles as the confirmation (it lands in the body's activation log); deactivate has a confirm stage and shows furrow's `previous` suggestion in the note. The `closed` row **carries both `done` and `reopen` in one row** (it reads the box's state to pick the verb; two rows would always leave one dead). The confirm stage says what furrow does not — **furrow closes a box with open members at exit 0**, so reporting the remaining count is this row's job alone — and the count is furrow's own set, the members in a non-terminal lane (`Board.OpenMembers`); a member parked in icebox/waiting is shown as `parked`, because `Total − Done` counted it as open (t-321c). The landing note carries furrow's `open_members` disclosure: the ids left open, and which of them recur (a repeating member's successor files under the closed box until it is re-filed); furrow's null (it could not read the board after the write) reads `unknown`, never `nothing left open`. `reopen`'s wording is furrow's own "OPEN and INACTIVE"; activation does not chain. A box just `done` still resolves through `Epic()`, so the overlay does not close on its own write and `reopen` is one key away. |
| **sort (Table)** | `o` cycles canonical → updated → created → value → effort → due (each key enters in its natural direction; pressing again flips). The current sort shows as `▲▼` on the matching column header plus `sort <key> ▲▼` in the filter bar at all times (created / effort have no column, so only the latter). Clicking a sortable header cell does the same (same cell again flips; `lane` returns to canonical). The order is a local stable sort over the same snapshot; unset values (no due etc.) go **last in both directions**. While sorted, `K`/`J` reordering is refused (as in GH). The task asked for `s`, which collides with the slice panel, hence `o`. |
| **canonical** (order) | The Table's default order = the board itself (lane order → priority within the lane). The absence of a field sort; it has no direction. |
| **review stamp (`i`)** | Set the selected task's `reviewed` to now (the `furrow review <id>` equivalent). **`updated` does not move** — review changes no content, by furrow's definition (measured on the real binary; a contract test pins it). Applied optimistically via the persist queue; on the board the only change is the note and the `reviewed <ago>` stamp line in the peek (tasks never stamped get no line — "reviewed never" would nag every card on a board that does not review). Repo / epic reviews (`furrow review <repo\|epic>`) are out of scope. |
| **revisit lens (`f`)** | **A toggle that makes `furrow revisit -q` the verdict.** When on, the board is only the open tasks revisit flagged, the filter line carries a `↻ revisit` chip and the peek a `↻ revisit <code> <detail> · …` line (code/detail as furrow gives them — `furrow vocab revisit-codes`). The typed query and the slice go to furrow as `-q` and **the AND is furrow's** (ridge does not intersect verdicts). A lens rather than a filter word because dep_done and the like are a separate read `-q` cannot express. **Not part of the saved-view bundle** (a question to the board, not a way of showing it). `-revisit` headless (through Init, like `-filter`). |
| **note append (`n`)** | An input that appends one paragraph to the selected task's body (the `furrow note` equivalent — append plus an `updated` bump in one command). A light path that opens the edit overlay's input stage directly; `e`'s full `$EDITOR` remains separate. esc / an empty ⏎ closes without adding; each application closes after one paragraph. |
| **quick add** | The creation modal opened by `a` (`addmode.go`). Maps to `furrow add -s <focused lane>` and inherits the single-valued `label:`/`epic:`/`repo:` (and `is:draft`) of the active filter (shown as chips — never attached silently; GH's filtered-metadata inheritance rule). After commit: re-read → select the new card (pinned if the filter hides it). |
| **inline token (quick add)** | Detail specifiers typed into the title line (`addparse.go`). `value:4 effort:2 due:+1d repeat:weekly dep:t-x check:"…" ref:… is:draft` = the same-named `furrow add` flags; vocabulary shared with -q (value/due/is:draft) is spelled the same. `repeat:` needs a `due:` on the line (furrow's `--repeat needs a --due`, refused live in either order), is quoted for the spellings with spaces (`repeat:"every 2 weeks on mon,thu"`), and its grammar stays furrow's — a rule furrow refuses comes back as the refusal note, the line reopened when the modal can be (`reopenRefusedAdd`: from the board's normal mode only, not under a full-screen view or the help overlay). Headless: `-demo addrepeat`. Other `is:` values are derived states that cannot be stamped at creation, so they are refused with a reason. Quotes are special in **exactly two places** — at the head of a field (that field is then always title text = the escape hatch for a title containing `value:`) and right after a token key's `:` (carries a check with spaces) — and literal everywhere else, so `Don't` and `彼は"これ"` reach the store intact. Inherited keys (`label:`/`epic:`/`repo:`) and focus-derived keys (`status:`/`lane:` — the target is the focused lane) are not swallowed but **refused, each with its own reason**. The chip line echoes live on every key, and an invalid token (non-numeric, outside 1..5, due grammar, an empty ref) gets a ⚠ line plus an in-modal refusal (the line survives). Multi-line paste creation (`--stdin`) is out of scope — the CLI is the right tool. |
| **draft** | A task with no repo attached — furrow's definition as is (born from `add --draft`; `furrow ls` hides them by default). ridge always reads them (an empty `-r` on load) and always shows them: card/Table put a dim `draft` in the repo slot, peek/graph say `draft (no repo)`. Filtering is the `is:draft` pass-through. Creation is the inline token `is:draft` or inheritance under an `is:draft` filter (a plain creation in the draft view is born with a repo and **vanishes on the spot**, so inheritance is the default). `--draft` conflicts with `-r` (furrow's refusal), and a conflict with an inherited repo gets a ⚠ line plus an in-modal refusal. **Promotion = attaching a repo in the edit menu** (`furrow repo --add`); there is no draft-specific gesture. |
| **pin** | Temporarily inserting one card into the board when a jump lands on a blocker the filter hides, so the jump does not miss. |

## Display vocabulary

| Mark | Meaning |
|---|---|
| `▸` | **actionable** — in the next lane with every dependency done (= can start now). |
| `x` / `x1` | **blocked** — an open task with open blockers (the number is how many). **Marked, not hidden** (hiding is `furrow next`'s job). A task closed while a blocker was still open (furrow permits it) is done, not blocked: every ridge surface that says a task is blocked — marker, card and graph badges, the peek's meta line, the strip's head, the dep map's counts — reads done first (`Graph.OpenBlockedBy`); the dep listings (the peek's blocked-by list, the strip's "blocked by N open" line, the table's open/total cell) still name the open dep. furrow's own `is:blocked` still matches such a task, so a `-q is:blocked` board can carry rows drawn `v`. |
| `▶` / `◆` / `v` | The lifecycle marks on the slice panel's epic rows. `▶` = the box this repo is working out of now (the same glyph as `furrow brief`), `◆` = pinned, `v` = closed (shown only after `z` widens the scope). In the `slice panel` `v` and `▶` share the **leading lifecycle column** and are exclusive there — furrow drops `active` when it closes a box, so the two cannot collide. `◆` is **not** in that column: furrow keeps `pinned` on close (measured), so `v` + `◆` is a legitimate pair and it rides the head of the suffix where it can be said alongside. The `box overview`'s marker column diverges deliberately — it is a third rung there (`closed > active > pinned`, exclusive), which it can afford because it is not the surface `z` reaches for a closed box. So an open pinned box carries `◆` in the panel's suffix and in the overview's column. All of them are `epic ls --all --json`'s `active`/`pinned`/`closed` shown as is. |
| `▤` | The **epic chip**. An epic is a separate entity without a lane (`EpicInfo`); the card shows the owning epic's resolved title. Warn-coloured if the epic is stuck. The peek adds `(done/total)` and STUCK, and while the epic waits on open deps a resolved `epic waits on` line (open: `id (d/t) title`; stuck: `id (d/t) STUCK title` in warn colour; a dep furrow already resolved out of `open_deps` reads **`(closed)` if the board holds that box as closed, otherwise furrow's weaker word `(satisfied)`**. Open/satisfied is furrow's derived judgement; ridge does not recompute it). |
| `v` | done. |
| `◆` (in a Roadmap row) / `┊` | The due's position (overdue = danger colour, same cell as today = warn colour) / the today line. A `◆` panned out of the window becomes `▸`/`◂` at the row's edge — a dated row must never look undated. |
| `[+]` / `[-]` | A Swimlane band folded / unfolded. ASCII because **every triangle is taken** by `▸` (actionable), `▶` (active box), `◆` (pinned) and `▼`/`▶` (the Graph's arrowheads). (The first version said "`⊞`/`⊟` are East-Asian Ambiguous" here; measured, both are Narrow and the reason was **backwards** — corrected in review.) |
| `·` (in a Swimlane band header) | No task in that lane. Not written as 0 because, reading a histogram down, what the eye should pick up is numbers, not absence. U+00B7 is East-Asian Ambiguous, but it is in the same family as the `◆`/`┊`/`▤` the board already uses, and `lipgloss.Width` measures it as 1. |
| `↻` | The **revisit lens** is on. Shown in the filter line's chip and the peek's reason line. Not on cards — surviving is the mark, and the reason is the peek's job. |
| `⟳` | **repeats** — the task carries a recurrence rule (`Task.Repeat`, furrow's compiled RRULE; the `repeats` tag `furrow ls` prints; `has:repeat`). On the card's meta line and beside the Table's due; the peek prints the rule and its series start (`⟳ repeats FREQ=… (since <day>)`, `furrow show`'s two facts). **Closing the task is what writes the next occurrence** — `d`, or a move into the done lane (`furrow set -s done` advances a series exactly as `done` does) — and the status line then says so in `furrow done`'s words (its `seriesLine`; ridge prints the due as the board-calendar day where furrow prints the instant): `closed <id> · repeat: next due <day> (<new-id>)`, `series complete — no further occurrences`, `— N occurrence(s) skipped` — appended to the gesture's own line (`closed <id> — unblocked N task(s)`, `respaced …`), never replacing it. The successor's card lands with the reconcile re-read, in furrow's default lane; the cursor stays where the close left it. The optimistic close drops the mark at once (furrow consumes the rule; a reopen does not hand it back). ridge expands no rule; the edit menu's repeat row and quick add's `repeat:` token write one (the `furrow set --repeat` / `add --repeat` mirror — see "edit menu"), and the grammar stays furrow's. Deliberately not `↻`: the peek can show both marks on one panel. Headless: `-demo repeat` / `-demo repeatdone`. |
| `[0/7]` | Checklist progress. |
| `v5 e4` | value / effort (each 1..5). |
| `◉ focus` | The Graph's root node. |
| `↕ both directions` | In the Graph, a node that appears both upstream and downstream of the root (`↔` in left-right). When the box width runs short, `◉ focus` → the repo chip → this mark are dropped in that order — the id and the lane always survive. |
| `↩` | An already-shown node (reached by a second path = the mark of a DAG). Avoids duplicates in the tree display. |

## Internals

| Term | Meaning |
|---|---|
| **overlay shell** | The stage machine the edit overlay and the epic overlay share (`internal/ui/overlay.go`): menu → sub-editor, where a sub-editor is a **gate** (one keystroke — the task's 1..5 pick, the box's ⏎ confirm), a **list** (a cursor over rows) or a **text input**; `esc` walks back one stage and closes from the menu (in the input stage the overlay decides where esc lands — the task's note input closes the whole overlay). Generic over the overlay's field and input-kind enums, so each overlay keeps its own typed switches. What a field *means* — what opening it shows, what ⏎ writes — is the overlay's, reached through `overlayHooks`; the shell reads no task or box and issues no write; the one status row it writes itself is the rolling-back refusal of a typed input. The epic overlay's creating modal is answered before the shell and never enters it. |
| **measurer** | The card-height cache (`internal/ui/layout.go` — layout and hit testing are built from the same measurement). **Held across frames** — per frame, the scroll-limit computation renders every card every frame, 36ms/frame at 658 tasks (measured; 3.3ms across frames). Discarded by `recompute()` — using a stale height after the content changed puts the drawing and the hit test out of step. |
| **ego-graph** | The dependency subgraph within N hops of one task. Its ranks are the longest path inside what the radius included, not the radius: a node one hop away that also ends a longer path sits at the end of that path, so every edge steps outward and only a cycle folds one (`egoLayout.Skipped`). On the real data at design time (2026-08): at most 12 nodes, 6 ranks (a longest chain of 5 edges), a widest rank of 4 (numbers that move with the board — in the open scope on 2026-09-03: at most 10 nodes, 4 ranks; on the 100-task ridge-test store a radius-2 graph reaches 10 ranks). |
| **hop radius** | How many hops the ego-graph follows. `z` / `1` `2` `3` `0` switch it. The Graph's other knob is **orientation** (`o`). |
| **re-root** | Making a Graph node the new root (`Enter`). A gesture for walking rather than reading; it cannot be a still image. |
| **`-dump`** | The flag that writes one frame to stdout with no TTY and exits. The foundation of headless verification. The fixture, unless `-live`. |
| **`-demo`** | Freezes a transient state that is hard to catch by hand (mid-drag, an edit sub-editor, a failure display …) into one frame and `-dump`s it. The name list is canonical in `ui.DemoNames` (`ridge -h` prints from it; a copy here went stale twice). The fixture's instrument: its states lean on the fixture's synchronous answers, one of them (`sweeprestore`) writes through the provider, so it is refused with `-live`. |
| **`-graphlr`** | The flag that `-dump`s the Graph left-right. Not a `-demo` because the orientation is not a transient state but a **view setting** (like `-table`) — as a flag, every existing graph `-demo` renders both ways without a copy per state. |
| **`-readonly`** | Emits the fixture as a board made read-only by the schema gate. A property of the store, not a model state, so a flag rather than `-demo`. Every write is refused. |
| **`-live`** | The `-dump` modifier that draws the **real store** — the cwd's board, or `FURROW_DIR`, whichever furrow resolves — instead of the fixture. Not golden material: the frame carries the load time and today's relative dates, and the board moves. Its job is the invariants (every line within `-cols`, no panic) and eyes on the real shape, which the fixture's uniform titles cannot stand in for (t-360e; the scratch probe it replaces is the `ridge-real-store-headless-probe` memory). Refused without `-dump` (the interactive session is live already), with `-mock`/`-readonly`, and with `-demo` — the views only `-demo` reached are the opening-view flags. What a live store answers as Cmds (the `-filter`/`-revisit` verdicts, the sweep's preview read) is settled inside `Dump` before the frame, where the fixture answered inside `New`. Reads the machine's `views.toml` no more than any other `-dump`; `-perflog` is honoured (the reads are furrow execs). |
| **opening-view flags** (`-table` / `-roadmap` / `-graph` / `-map` / `-boxes` / `-swim` / `-sweep`) | Open on that view. A view is a setting, not a transient state, so each is a flag (the `-graphlr` reasoning): it opens the interactive TUI there too, and it composes with `-live`. Exactly one per invocation; `-peek`/`-tree` are refused with every full-screen one (no side panel to open — `-table -peek` is honoured). The graph roots on the opening cursor (the first card of the first lane with work; a board with no card stays on the board). Each runs the view's note-free `start*` half inside `ui.New`, so the read-only warning survives (`-readonly -roadmap` lost it once). |
| **the one clock** (`board.Now` / `board.Zone`) | The instant and the calendar every package reads — `ParseDue`, the overdue and staleness predicates, every date rendering — from one pair of vars in `internal/board`. `Zone` is the **board's calendar**: furrow's `[due].timezone` as `furrow board --json` reports it, declared by the store on every load (`board.SetZone`; the fixture declares JST, the zone its dues are bound in), and the process zone only while the board declares none — furrow's own fallback. Not the terminal's `TZ`: a due bound at 23:59:59 Asia/Tokyo is the next day in Auckland, and every date ridge draws must be the day furrow prints (t-kt2h: `-dump -live` under two `TZ` values is identical). Tests pin both through `board.SetClock` — the zone pin outranks any declaration until restored, so a store built inside a pin cannot half-freeze the clock — never `time.Local` (a write there races the runtime's timer goroutine). It is one clock because it was three: ui, board and memstore each had a private copy pinned only by its own tests, and a due parsed in the runner's zone rendered in the pinned one a day off (t-xy0c). |
| **`-debuglog`** | The JSONL record of a session's operations (one event per line, append-open, each session starting with `session/start`). Five layers: input / mode / apply / persist / status. Three hook points — the single path through `Update` (input, mode, apply and the persist queue events) / the store's perf hook (exec; crosses goroutines, serialised by a mutex) / the `note`/`fail` funnel (status). Keystrokes are kept in full — only task bodies are not recorded. A different job from `-perflog` (the raw material for latency measurement — two-column TSV, `-benchload`-compatible); the two can be combined. Cannot be combined with `-dump`/`-benchload` (there is no session to record). |
